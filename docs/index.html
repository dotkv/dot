Getting started

A small, log-backed key-value store embedded in your Go application.

Dot stores typed values in sharded, append-only logs and rebuilds its in-memory index when opened. It includes atomic updates, expiration, background compaction, and an embedded metrics dashboard.

Run the demo

Use the Go toolchain required by go.mod (currently Go 1.27.2). Dot uses Unix file locking and anonymous mmap; the benchmark suite targets Linux. From a checkout, start the bundled workload and dashboard:

git clone https://github.com/dotkv/dot.git
cd dot
go run -buildvcs=true ./fiddle

Open localhost:8080/dot/metrics/. The demo creates a temporary database under /tmp and continuously exercises sets, gets, updates, and deletes. Press Ctrl+C to stop.

Open a database

Add Dot to your application:

go get github.com/dotkv/dot

This complete program writes a string and reads it back:

package main

import (
	"fmt"
	"log"

	"github.com/dotkv/dot"
)

func main() {
	db, err := dot.Open("data")
	if err != nil {
		log.Fatal(err)
	}
	defer db.Close()

	if err := db.Set("greeting", "hello"); err != nil {
		log.Fatal(err)
	}
	greeting, err := db.Get[string]("greeting")
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(greeting) // hello
}

To use a local checkout from another Go module, point a local replacement at it (adjust ../dot to the checkout's path), then add the program and tidy:

go mod edit -require=github.com/dotkv/dot@v0.0.0 -replace=github.com/dotkv/dot=../dot
go mod tidy

Open creates a missing directory or recovers an existing database. One process can open a database path at a time; goroutines share the same *dot.DB. Close releases resources and keeps the files. Destroy closes the database and removes its directory.

Configure writes

db, err := dot.Open("data",
    dot.WithShardCount(16),
    dot.WithSync(true),
    dot.WithCompactionThreshold(0.4, 1<<20),
)
OptionDefaultBehavior
WithShardCount(count)64A power of two from 1 to 1024. Sets the layout of a new database; an existing database keeps its stored count.
WithSync(enabled)falseSyncs changed writes before returning. Can also be set per mutation.
WithExpiration(time)No expirationAn absolute expiration time. Can be set on Open, Set, or Update; a zero time clears it.
WithCompactionThreshold(ratio, bytes)0.33, 1 MiBQueues maintenance above the obsolete-byte ratio and minimum bytes per shard.

By default, successful writes rely on the OS page cache and are not individually synced. Use WithSync(true) when a mutation must sync its log before returning. See storage and recovery for the durability and maintenance details.
