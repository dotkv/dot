Storage & recovery

Choose durability settings and manage a database in your application.

Database access

Keep the database on local storage and share one *dot.DB across goroutines. A second Open of the same path, including from the same process, fails with an error wrapping ErrDatabaseLocked. Check it with errors.Is(err, dot.ErrDatabaseLocked). The lock is released when the database closes or the process exits.

Durability

By default, successful writes reach the OS page cache. Use WithSync(true) when writes must be synced to storage before returning:

db, err := dot.Open("data", dot.WithSync(true))

This default applies to Set, Update, and Delete. You can also choose it per call. Syncing costs a storage flush for each changed write, so expect lower throughput. Close releases resources; it does not replace choosing synchronous writes.

Reopening and recovery

Open recovers existing data automatically. Startup time grows with the retained log history. An incomplete final write is discarded; checksum failures and other corrupt records cause opening to fail.

Back up the entire database directory after closing it. A copy made while writes or background cleanup are running is not a consistent backup. Keep the directory's metadata and data files together.

Database options

New databases default to 64 shards. Choose a different count at creation if needed:

db, err := dot.Open("data", dot.WithShardCount(16))

The count must be a power of two from 1 to 1024. Reopening without this option uses the stored count; an explicitly different count fails. Changing the count or opening an unsupported format requires a data migration, which is not yet automatic. Open reports the reason as a migration failure and leaves the existing data unchanged. Missing or invalid metadata also fails opening.

Background cleanup

Dot automatically reclaims overwritten, deleted, and expired data. Expired keys read as missing immediately, but their disk space is reclaimed later. Cleanup can temporarily block operations on the shard being processed and needs room for a temporary output file.

The defaults suit most applications. To change when overwritten and deleted history triggers cleanup:

db, err := dot.Open("data",
    dot.WithCompactionThreshold(0.4, 1<<20),
)

This queues cleanup when more than 40% of a shard's retained data is obsolete and at least 1 MiB is obsolete. The defaults are 33% and 1 MiB per shard. The ratio must be in [0, 1); the minimum can be zero. Larger thresholds trade more disk usage for less frequent cleanup. These are scheduling thresholds, not disk-space limits. The dashboard shows disk usage and obsolete bytes.
