Development

Run checks and benchmarks, and maintain the static documentation.

Checks

From the repository root:

go test ./...
node --test metrics_ui/app.test.cjs metrics_ui/app_test.js
(cd benchmarks && go test ./...)

The test workflow runs these checks on every pull request, including new commits to an open pull request, and on pushes to master.

Benchmarks

Run the library benchmarks with go test -run '^$' -bench . -benchmem. The comparison suite is a separate module; its README describes workloads, commands, and results.

Persistent metrics history is opt-in and defaults to zero (disabled). The comparison suite creates no metrics handler, so it performs no dashboard collection. For application benchmarks, keep viewers disconnected and history disabled to avoid measuring dashboard overhead. The library's BenchmarkOperationMetrics compares recording disabled, an idle default handler, counts only, and latency timing.

Releases

Push a semantic version tag to publish a Go module version:

git tag v0.1.0
git push origin v0.1.0

Create GitHub Releases manually from the repository's Releases page, selecting an existing tag or creating a new semantic version tag. For tags such as v0.1.0-rc.1, mark the release as a prerelease.

Preview the docs

Edit the HTML, CSS, and JavaScript in docs/ directly. No build step is needed.

python -m http.server 8000 --directory docs

Open localhost:8000.

Publish the docs

The Pages workflow deploys docs/ to dotkv.github.io/dot/ when documentation changes reach master. Select GitHub Actions as the source in the repository's Pages settings.
