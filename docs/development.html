Development

Run checks and benchmarks, and maintain the static documentation.

Checks

From the repository root:

go test ./...
node --test metrics_ui/app.test.cjs metrics_ui/app_test.js

The comparison benchmarks live in a separate module and are not included in the root go test ./... command.

Benchmarks

The engine comparison suite compares Dot and Pebble using 16-byte keys and 16 workers by default. It covers 80/20 and 20/80 read/write ratios with 8-byte scalars and 1 KiB values. Dot and Pebble use normal automatic compaction. A short Dot probe estimates fixed operation budgets targeting about 15 seconds per Dot case. Every engine runs the same operation count. The suite reports latency, throughput, RSS, and disk usage, and always writes results to its README after a successful run. Dependencies live in a separate module.

Root benchmarks include serial, unchanged, and parallel uint64 updates. Their primitive fixtures stop background maintenance to isolate foreground work and keep direct file/index resets deterministic.

go test -run '^$' -bench '^BenchmarkUpdateUint64' -benchmem

Compare dashboard recording overhead with:

go test -run '^$' -bench '^BenchmarkOperationMetrics$' -benchmem

Compare growth and shrinking at their respective occupancy thresholds, using the same source capacity and random or heavily clustered runs:

go test -run '^$' -bench '^BenchmarkIndexResize$' -benchmem

Releases

Tag the release commit and push the tag:

git tag v0.1.0
git push origin v0.1.0

Go resolves module versions directly from pushed semantic version tags. The .github/workflows/release.yml workflow runs the Go tests, benchmark adapter tests, and dashboard tests, then creates a GitHub Release with generated notes. Tags such as v0.1.0-rc.1 are marked as prereleases. No generated version file, linker flags, or additional repository secret is needed.

Preview the docs

The docs/ directory contains ordinary HTML, CSS, and JavaScript. Edit these files directly; no package installation, bundler, or site generator is needed. All page and asset links are relative so the site works under /dot/. Serve the repository root to preview the site under a directory prefix locally:

python -m http.server 8000 --directory .

Open localhost:8000/docs/. Code-copy buttons use the Clipboard API where supported; the documentation and navigation also work without JavaScript.

Publish with GitHub Pages

The project site is dotkv.github.io/dot/. In the repository's Pages settings, choose GitHub Actions as the build and deployment source. For a private organization repository, Pages requires an eligible GitHub plan.

The workflow at .github/workflows/pages.yml uploads only docs/ and deploys it directly. It runs when those files or the workflow change on master, and can also be run manually from the Actions tab on master. It uses the github-pages environment and the repository's GITHUB_TOKEN; no custom deployment secret is needed. See GitHub's custom workflow documentation for the Pages setup and permissions.

Project or organization site

This repository publishes a project site, at https://dotkv.github.io/dot/. The organization root, https://dotkv.github.io/, requires a repository named dotkv.github.io. A project repository does not become an organization site just because an organization owns it. See GitHub's site types.
