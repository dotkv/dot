Usage

Read, write, update, and expire typed values.

Typed values

Keys accept string or []byte; "a" and []byte("a") address the same key. Values support []byte, string, bool, int, int8, int16, int32, int64, uint, uint8, uint16, uint32, uint64, float32, float64, and time.Duration.

if err := db.Set("counter", uint64(42)); err != nil {
    return err
}
value, err := db.Get[uint64]("counter")

Get[T] and Update[T] require the stored type; there are no implicit conversions. A mismatch returns an error wrapping ErrTypeMismatch; check it with errors.Is(err, dot.ErrTypeMismatch). Set can replace a value with a different type. Byte slices returned by Get belong to the caller and may be changed or retained.

Fixed-width numbers use their natural byte widths in little-endian order; floating-point values preserve their IEEE 754 bits. int and uint always use eight bytes on disk and have distinct tags from int64 and uint64. Reading a value that does not fit the host's int or uint returns an error wrapping ErrValueOverflow. For example, db.Set("count", 42) stores an int that is read with db.Get[int]("count").

time.Duration stores signed nanoseconds in eight little-endian bytes and retains its own type. Store with db.Set("timeout", 5*time.Second) and read with db.Get[time.Duration]("timeout").

Delete and handle errors

Get returns ErrNotFound directly for a missing or expired key, so compare with ==. Other errors may wrap a cause; use errors.Is when checking those.

value, err := db.Get[string]("greeting")
switch {
case err == dot.ErrNotFound:
    fmt.Println("missing or expired")
case err != nil:
    return err
default:
    fmt.Println(value)
}

db.Delete("greeting") removes a key. Deleting a missing or expired key succeeds unless a WithCondition predicate rejects it.

ErrorMeaning
ErrNotFoundThe key is missing or expired.
ErrTypeMismatchThe requested type differs from the stored value.
ErrDatabaseLockedAnother Open holds this database path.
ErrInvalidValueA stored record has invalid data.
ErrValueOverflowA stored integer does not fit the host type, or integer arithmetic would overflow or underflow.
ErrConditionFailedA mutation's predicate returned false; the key is unchanged.
os.ErrClosedThe database has been closed.

Expiration and durability

WithTTL sets a lifetime relative to each write. The key becomes unreadable when that lifetime ends, even before cleanup removes its data:

err := db.Set("session", "active",
    dot.WithTTL(15*time.Minute),
    dot.WithDurability(dot.Sync),
)

A WithTTL option can be reused or passed to Open as a default; the deadline is calculated after acquiring the shard lock and running any update callback. Set uses the default unless overridden. Update, Add, and Sub preserve an existing key's deadline; an insert uses the default. Pass WithTTL explicitly to start a fresh lifetime. A zero TTL clears expiration; a negative TTL expires immediately. Deadlines outside the disk format's timestamp range are clamped to its nearest limit.

WithExpiration takes a fixed time.Time instead. A deadline passed to Open is shared by all writes that use that default. dot.WithExpiration(time.Time{}) clears expiration. When combined with WithTTL, the last option wins. Expiration options have no effect on Delete. Written deadlines survive reopening; Open options are configured anew on each open.

Writes use dot.Buffer by default: each active shard buffers up to 64 KiB and writes to the file without fsync within 100 ms or when full. Reads see buffered records immediately. Pass WithDurability (dot.Buffer, dot.Write, or dot.Sync) on any Set, Update, Add, Sub, or Delete call to override the database default for that write.

Atomic updates

Update reads, transforms, and writes one key atomically:

err := db.Update("counter", func(current uint64, exists bool) (uint64, error) {
    return current + 1, nil
})

A missing or expired key passes the type's zero value with exists == false: 0 for numbers, "" for strings, false for booleans, or nil for byte slices. Returning an error aborts the write and returns that error unchanged. To update only existing keys:

err = db.Update("message", func(current string, exists bool) (string, error) {
    if !exists {
        return "", dot.ErrNotFound
    }
    return current + "!", nil
})

The callback runs once while writes to its shard are locked. Keep it short and do not call methods on the same database from it. A type mismatch fails before the callback runs. Byte slices passed to the callback belong to the caller; returned bytes are copied. Returning nil bytes with no error stores an empty value.

Atomic arithmetic

count, err := db.Add("counter", uint64(1))
count, err = db.Sub("counter", uint64(1))
timeout, err := db.Add("timeout", 5*time.Second, dot.WithTTL(time.Hour))

Add and Sub atomically change one numeric value and return the new value. They accept every numeric type supported by Dot, including time.Duration. The delta's type must match the stored type; for example, db.Add("counter", 1) uses int and cannot update a stored uint64.

Missing and expired keys start at zero. Integer overflow or underflow, including subtracting a positive unsigned value from a missing key, returns an error wrapping ErrValueOverflow without changing or inserting the value. Floating-point operations follow Go arithmetic, including infinities and NaNs. On any error, the returned value is zero. Expiration and durability follow Update. The dashboard counts both methods as updates.

Conditional mutations

WithCondition permits a Set, Update, Add, Sub, or Delete only when its predicate returns true. The predicate sees the current value and runs under the same shard lock as the mutation. This makes application limits atomic:

count, err := db.Add("active-jobs", 1,
    dot.WithCondition(func(current int, exists bool) bool {
        return current < 100
    }),
)

For compare-and-delete, check the current owner:

err := db.Delete("lock", dot.WithCondition(
    func(owner string, exists bool) bool {
        return exists && owner == myToken
    },
))

Missing and expired keys pass the predicate's zero value and exists == false, even when an expired record had a different type. A live value must match the predicate's type; mismatches return an error wrapping ErrTypeMismatch before the predicate runs. Set may write a different type after the condition passes. Update, Add, and Sub also require their own value type to match the stored value.

The predicate runs once before an update callback or arithmetic. Returning false returns ErrConditionFailed directly, without calling the update callback or applying the mutation, expiration options, or durability request. Integer overflow checks still apply after an accepted condition. Add and Sub return zero on failure.

Keep predicates short and do not call methods on the same database from them. Byte slices passed to predicates belong to the caller and can be changed or retained without affecting the stored value or an update callback's input. A panic propagates without applying the mutation. A later storage error cannot undo a predicate's external effects. A nil predicate returns an error. Conditions may be reused across operations; the last WithCondition option wins. Open rejects conditions; pass them to individual mutations.

Scan

for entry, err := range db.Scan() {
    if err != nil {
        return err
    }

    switch v := entry.Value.(type) {
    case string:
        fmt.Printf("%s: text %q\n", entry.Key, v)
    case []byte:
        fmt.Printf("%s: bytes %x\n", entry.Key, v)
    case bool:
        fmt.Printf("%s: flag %t\n", entry.Key, v)
    case uint64:
        fmt.Printf("%s: counter %d\n", entry.Key, v)
    case time.Duration:
        fmt.Printf("%s: duration %s\n", entry.Key, v)
    default:
        fmt.Printf("%s: %T = %v\n", entry.Key, v, v)
    }
}

Scan returns iter.Seq2[dot.Entry, error]. An entry has a Key []byte and a Value any decoded to its stored Go type. All supported value types retain their identity, including distinct string and []byte values, native int and uint, and time.Duration. Expired and deleted keys are skipped.

A read or decoding failure yields a zero entry and an error once, then stops. Use errors.Is to inspect wrapped errors. Scanning a closed database yields an error wrapping os.ErrClosed. Reading a stored native integer that does not fit the host type yields an error wrapping dot.ErrValueOverflow.

A scan visits shards in order, with no ordering within a shard, and is not a snapshot. Writes to shards not yet scanned become visible; writes to scanned shards do not. It holds each shard's read lock while visiting it, so do not call methods on the same database inside the loop. Keys and []byte values are reused across iterations; copy them to retain them. Strings and scalar values can be retained directly.
